# DynEst - Software Effort Estimation from Customer Requirements (dynamic, soft-computing pipeline)

PBL project for *Fundamentals of Soft Computing Lab (26B16CS311)*, JIIT Noida.
Implements the synopsis: **Requirement change → Effort re-estimation → Schedule optimisation**, automatically.

## Quick start
```bash
python -m venv venv && source venv/bin/activate      # Windows: venv\Scripts\activate
pip install -r requirements.txt
streamlit run app.py          # web dashboard
python run_demo.py            # same pipeline in the terminal
python -m pytest -q tests     # 9 unit / integration tests
```

## Synopsis step → code
| Step | What | File |
|---|---|---|
| 1 Requirement attribute ingestion | complexity, clarity, integration, experience, size, priority, ui/backend/data profile | `dynest/data.py`, table in `app.py` |
| 2 SOM clustering | 4x4 Self-Organizing Map (numpy); neurons labelled UI-heavy / Backend-intensive / Data-processing | `dynest/som.py` |
| 3 ANFIS sizing | first-order Sugeno ANFIS, Gaussian MFs, hybrid learning (LSE + gradient descent) → complexity rating | `dynest/anfis.py` |
| 4 Mamdani FIS | 125 linguistic rules, min-AND, min-implication, max-aggregation | `dynest/mamdani.py` |
| 5 Centroid defuzzification | crisp person-days per story point → effort, duration, team capacity | `dynest/mamdani.py`, `dynest/pipeline.py` |
| 6 Dynamic requirement tracking | diffs the backlog (ADDED / DROPPED / MODIFIED), re-runs steps 1-5, stores delta snapshots | `dynest/tracker.py` |
| 7 GA + PSO optimisation | concurrent sprint/developer allocation, same fitness & budget | `dynest/optimizers.py` |
| 8 Explainability + confidence | fired rules + firing strengths; ±1.96σ band | `app.py` (tab "Why this estimate"), `dynest/pipeline.py` |

## Data note
No public dataset has requirement-level attributes, so `data/historical_requirements.csv` is **synthetic** (900 requirements, generated by `dynest/data.py` using COCOMO-style cost-driver logic plus noise). To use real data, replace the CSV keeping the same columns (`ui, backend, data, complexity, integration, clarity, experience, size_points, assessed_complexity, actual_effort`). Say this clearly in your report/viva: accuracy numbers are on synthetic data.
